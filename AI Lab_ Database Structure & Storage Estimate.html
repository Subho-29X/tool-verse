AI Lab: Database Structure & Storage Estimate

Everything on the Mac mini: PostgreSQL, the member and admin web UI, login, bookings, guardrail logs and uploaded files, The Mac mini's 512 GB internal drive holds the software, and the 4 TB external SSD holds only lab data (database, uploads, logs).

2. Member view and admin view (web portal and API)

There is no chat screen. The lab is used only through API endpoints with an API key. The web portal on the Mac mini is for bookings, keys, usage and administration. Login (SSO) decides which screens appear, and Postgres row-level security makes sure members can only read their own rows.

Member view

  • API requests: members call the lab through API endpoints with their own key. Each call is saved as a session and messages, and members can review their own request history and uploaded files (chat_sessions, messages, attachments)
  • Book a slot: pick a node and time, see own bookings and their status (bookings)
  • My usage: own tokens and requests (usage_daily)
  • My API keys: create or revoke own keys (api_keys)
  • Blocked or masked requests: see which of their own API calls were masked or blocked, and why (own rows of guardrail_events)

Admin view

  • Users and teams: invite, suspend, change role and token limit (users, departments)
  • Bookings: approve or reject, see the calendar for both Studios (bookings)
  • Nodes and models: online or maintenance, which model is on which port (nodes, models, node_models)
  • Safety: guardrail hits by user, category and checker (guardrail_events)
  • Audit log: who did what, from which IP (audit_logs)
  • Reports and health: usage per team, latency, storage left (usage_daily, Grafana)
Login itself (passwords, MFA, SSO sessions) lives in the identity system (Keycloak or Authentik) with its own small database. The users table keeps only the SSO id, so passwords never sit in your app tables.

Assumptions behind the numbers

ItemAssumption
Text size1 token is about 4 bytes of English text.
Chat messagesPrompt and reply stored twice (original plus redacted copy), about 350 bytes of row data per message, plus 30% for indexes.
Guardrail eventsAbout 5 check rows per exchange (Presidio, Gitleaks, Qwen3Guard on the prompt, plus output checks), about 350 bytes each.
App and proxy logsAbout 1.5 KB per exchange across LiteLLM, the proxy and the UI.
Logins, audit, bookings3 logins and about 12 audit events per active user per day (about 450 bytes each), and 2 bookings per user per week (about 700 bytes each).
Metrics (Prometheus)About 10 MB per day for two Studios and the mini, at 15-second scrapes.
UploadsStored as files on the SSD, not in the database.

4. Storage on the Mac mini: internal drive vs external SSD

Internal drive: 512 GB

macOS, containers and software, and the guard models (Qwen3Guard, Presidio). This is a fixed size of about 10 to 35 GB, so most of the drive stays free.

External SSD: 4 TB

Lab data only: the Postgres data folder, uploaded files, logs and metrics. This is the part that grows with use (see section 3). Keep backups on a different drive.

One-time footprint on the internal drive, before any user data:

ItemApprox. size
Containers and software (Postgres program files, Redis, LiteLLM, Keycloak, the member and admin portal, Prometheus, Grafana, proxy)8 to 15 GB
Qwen3Guard model (size depends on the variant you pick)1 to 16 GB

The big model files (DeepSeek V4-Flash, Qwen3-Coder-Next and so on) live on the two Mac Studios, not on the mini. Their 1 TB drives are for models only. On the mini, point the Postgres data folder and the upload folder at the external SSD (for example /Volumes/LabData) so user data never fills the internal drive.
